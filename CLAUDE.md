# skimatik - Claude Context

## What This Is

Database-first code generator for PostgreSQL. Generates type-safe Go repositories with CRUD operations, cursor-based pagination, and custom query functions from database schema and SQL files.

**Philosophy**: Your PostgreSQL schema is the source of truth. The database defines your domain model, not application code.

## Architecture

### Core Components

**`internal/generator/`**
- `sql_parser.go` - Parses SQL using wasilibs/go-pgquery (WASM-based, no CGO)
- `codegen.go` - Generates Go code from parsed SQL and schema metadata
- `schema_reader.go` - Reads PostgreSQL schema via information_schema
- `template.go` - Go template execution for code generation

**`cmd/skimatik/`**
- CLI entry point
- Config loading from `skimatik.yaml` or environment variables

**`configs/`**
- Default configuration structure

### Generated Code Pattern

For each table, generates:
1. **Repository struct** with `pgxkit.DBConn` and shared operations
2. **CRUD methods**: GetByID, Create, Update, Delete
3. **Pagination**: ListPaginated using cursor-based pagination (UUID v7)
4. **Custom queries**: From `.sql` files with semantic parameter names

Repositories designed for embedding into custom types:
```go
type CustomUserRepo struct {
    *generated.UserRepository
    // add business logic
}
```

## Using the Makefile

```bash
make build            # Build the skimatik binary

make clean            # Clean build artifacts and stop services
```

## example-app

**Purpose**: End-to-end validation that generated code works correctly in a real application.

**Location**: `/example-app/`

**Structure**:
- `database/migrations/` - golang-migrate SQL migrations
- `database/queries/` - Custom SQL query files for skimatik
- `repository/` - Custom repository wrappers (extends generated code)
- `repository/generated/` - Code generated by skimatik (DO NOT EDIT)
- `service/` - Business logic layer
- `api/` - HTTP handlers
- `skimatik.yaml` - Configuration for code generation

### example-app Makefile Targets

```bash
cd example-app

make setup         # Start database and run migrations
make generate      # Run skimatik to generate repository code
make test          # Run tests (auto-setup + generate + test)
make run           # Start the API server
make clean         # Clean generated code and stop database

# Migration management
make migrate-up              # Apply all pending migrations
make migrate-down            # Rollback one migration
make migrate-status          # Show current migration version
make migrate-create NAME=foo # Create new migration
```

### example-app Test Flow

When you run `make test` in example-app:
1. Auto-starts database if not running
2. Runs migrations
3. Generates code with skimatik
4. Builds the application
5. Starts the API server
6. Tests all endpoints with curl
7. Stops the server

## Documentation & Wiki

All documentation lives in `/docs/` as Markdown files. Push to `main` and the wiki auto-syncs.

## Key Files

- `go.mod` - Uses wasilibs/go-pgquery (WASM) + pganalyze types for SQL parsing
- `.goreleaser.yml` - Release config with `CGO_ENABLED=0` (required for wasilibs)
- `skimatik.yaml` - User config (database connection, tables, output paths)
- `Makefile` - Development workflow automation
- `.github/workflows/ci.yml` - CI pipeline

## Database Requirements

- PostgreSQL (any version pgx supports)
- Tables must have single-column primary keys (composite keys not supported)
- Uses `information_schema` for metadata

## Common Development Tasks

### Adding New Generator Features

1. Modify templates in `internal/generator/template.go`
2. Update `codegen.go` to pass new data to templates
3. Run `make test-example-app` to validate
4. Update relevant docs in `/docs/`

### Modifying SQL Parsing

1. Edit `internal/generator/sql_parser.go`
2. Uses `pg_query.Parse()` from wasilibs
3. Returns `*pg_query_go.ParseResult` (types from pganalyze)
4. Run `make test-unit` to validate parsing logic

### Testing Changes End-to-End

1. Make code changes
2. Run `make test-example-app` (builds, generates, tests)

### Creating Releases

1. Tag with semantic version: `git tag v0.x.x`
2. Push tag: `git push origin v0.x.x`
3. Release workflow automatically builds and publishes

## Build Notes

- CGO disabled in goreleaser for cross-platform builds
- wasilibs/go-pgquery provides PostgreSQL parser via WebAssembly
- Generated code only depends on pgx and pgxkit
